# 注释工程化 · 执行规范（执行者必读）

本文件是**唯一权威执行规范**。动手前完整读一遍；与你的默认习惯冲突时，以本文件为准。
配套权威规范（写什么、为什么）：`docs\注释规范.md`。

---

## 一、绝对约束（违反即任务失败）

1. **只允许修改注释**：Java 的 `//`、`/* */`、`/** */`；YAML 的 `#`；Lua 的 `--` 与 `--[[ ]]`。
2. **代码部分必须逐字节不变**：不改逻辑、不改结构、不改缩进、不改变量名/方法名/类名、不重排 import、
   不删代码行、不加代码行、不移动空行。
   - 唯一例外：*紧跟代码的行尾注释被删除后*，该行允许去掉行尾多余空格。除此之外行尾空白保持原样。
3. **不新增原注释里没有的、代码也看不出来的信息**（禁止臆造设计意图）。
   **允许**基于**该文件内可见的事实**纠正错误注释（类名、`@TableName`、字段口径、方法体行为、注解参数）。
4. 只改分配给你的文件，**绝不**碰其它文件（可以读任意文件）。
5. 不执行任何 `git` 命令；不运行 maven；不改动 `docs/` 下的文档。

---

## 二、目标风格：纯文本，不用 HTML，不用 Markdown 强调

这是本项目 2026-10 已统一过的既定风格，**回潮会被闸门拦下**。

**禁止**：
- HTML 标签：`<h3> <ul> <li> <p> <b> <pre> <br> <code> <table> <tr> <td>` 等一律去掉
- Markdown 强调：`**粗体**`、`*斜体*`、反引号包裹
- 装饰性分隔线：`// ===== xxx =====`
- 口语化：手滑、白填、踩坑、说白了、要命 等

**改用中文标记词分段**（每个标记词独占一段的行首，后接内容）：

```
【核心职责】 【设计意图】 【边界约束】 【注意】 【严禁】
【入参约束】 【返回】 【异常】 【风险】
【取值依据】 【调大后果】 【调小后果】 【关联配置】 【误传后果】
【返回值约定】 【fail 策略】 【为什么必须用 Lua】
【触发条件】 【不做后果】 【影响面】 【临时规避】
```

强调用实词（必须 / 禁止 / 严禁 / 一律），不要用符号。

保留 `{@code ...}`、`{@link ...}`（标准 JavaDoc 内联标签），但**不要新增**。

## 三、删什么（逐条核对）

1. **所有 HTML 标签**（含 `<pre>` 里的示例输出/日志片段 —— 属实测证据，直接删）。
2. **所有 Markdown 强调标记**。
3. **口语化表达**。
4. **历史叙述**：任何形如「改前是…」「原代码…」「原实现…」「初版…」「以前…」「本次修复…」「已删除」
   `【改前的问题】` `【改后】` 的内容。**改写为「当前的不变量是什么」，或直接删。**
5. **实测叙述**：`实测`、`复现验证`、`跑了一遍`、`控制台输出`、`日志里就能` —— 属历史证据，删。
6. **复述代码 / 逐行翻译**：普通 CRUD、getter/setter、显而易见的赋值、直白循环、简单参数校验。
7. **重复表述**：同一意思在类/方法/行内说了多遍 → 只留信息量最大的一处。
   接口注释与实现注释重复 → **接口只留契约**（1~2 行），"为什么"下沉实现类。
8. **相邻注解已说清的约束**：`@Pattern(regexp=..., message=...)`、`@NotBlank`、`@Schema(description=...)`
   上方不要再写一条同义中文注释。
9. **可配置项被写死的值**：`tokenTTL` 写成「（30 分钟）」会在配置变更后变成**错误注释**；
   改为不会漂移的表述，或用 `{@code llmall.jwt.tokenTTL}` 指路。
   （稳定事实相反：金额单位「分」、状态字典值、key 前缀语义**必须写**。）
10. **无信息量的 TODO**：裸 `TODO` / `TODO: 优化` → 补成规范格式或删除。

## 四、补什么（八类，按本组模块重点）

规范与模板见 `docs/注释规范.md` 第二节。执行时的判定标准：

| 类型 | 本次要检查的核心 |
|---|---|
| 类注释 | 一句话职责是否落到**业务**（不重复类名）；是否有【核心职责】/【设计意图】/【注意】 |
| 方法注释 | 公开方法是否有【入参约束】/【返回】/【异常】/【风险】；资金/库存/鉴权方法必须写误改后果 |
| 行内注释 | 是否**只**出现在幂等点、并发分支、状态流转、异常降级、历史缺陷修复点五类位置 |
| 风险警示 | 鉴权旁路用【严禁】；资金/库存口径/关联配置必须写「误改后果」 |
| 配置注释 | 超时/线程池/缓存 TTL/令牌 TTL 必须有取值依据 + 调大调小后果 + 关联配置 |
| Lua | 每个 ARGV 的语义+单位+取值范围；fail 策略；多副本互引 |
| SQL | 功能/背景/影响面/执行步骤/前置依赖/回滚方案 + 风险等级 |
| TODO/FIXME | `TODO(责任人, yyyy-MM-dd): 问题 —— 触发条件：…；不做后果：…` |

**方向提醒**：本次是**工程化**，不是单纯的「精简」。噪音要删，缺失的设计决策与边界约束要**补**，
与实现不符的要**改**。注释行数可增可减 —— 判据是每一行是否有信息量，不是行数多少。

**纠偏优先级最高**：注释与代码事实矛盾时必须更正，且更正依据只能来自文件内可见信息。

## 五、强制校验（必须自己跑，必须通过）

```
pwsh -File gates\gate.ps1 <相对 llmall 的路径> [更多路径...]
```

- 路径以**仓库根**为根（命令都在仓库根目录下执行）、**用正斜杠**。
- 输出 `结论: 通过` 且退出码 0 才算完成。
- 报 `[FP1 代码语义被改!]` 或 `[代码被改动!]` = 你动了代码，**必须还原那处代码**后重跑，直到通过。
- 报 `[FP2 格式被改 ]` = 代码的换行/书写形态被动了（例如把两行合成一行），同样必须还原。
- 输出里会给出「注释 N -> M 行，代码 X -> Y 行」，**Y 必须等于 X**。

另外自检你负责文件的**违规残留是否清零**：

```
pwsh -File gates\lint-comments.ps1 -Detail
```
在你改过的文件上不应再有 `[HTML标签]`、`[粗体标记]`、`[装饰横幅]`、`[历史叙述]`、`[实测叙述]`、`[变更叙述]` 命中。
