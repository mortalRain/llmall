# 搜索增量同步：旧消息不能把新资料改回去

搜索里的门店资料是副本，门店变更后通过消息更新本地MySQL读模型，再更新ES。以前时间被截成整秒，同一秒内的新旧消息无法分辨；并发请求也可能都先读到旧版本，再把后来的新资料覆盖掉。ES无条件写入还会让迟到请求、旧重建快照覆盖新文档。

本轮为增量链路补上三道保护：保留毫秒、锁内重查版本、ES原子比较版本。还把ES发送放在MySQL成功提交之后，避免增量事务回滚却把修改留在ES里。

## 数据库与提交边界

- 发生时间使用既有occurredAt毫秒值。缺失或非正数时拒绝，不拿收到消息的当前时间伪装成最新版本。
- event_time必须至少DATETIME(3)。新版启动guard在SmartInitializingSingleton阶段检查，早于Rabbit监听器SmartLifecycle启动；未迁移则启动失败。
- 原有普通select只判断是否需要初始化，不能裁决版本。缺行时用INSERT ... ON DUPLICATE KEY UPDATE shop_id=shop_id初始化/拿排他锁，避免初次创建冲突靠异常处理；空热点值沿用表的0/营业中默认语义。
- 随后SELECT FOR UPDATE当前读，对比实际已提交版本；只有严格更晚才更新。相同时间保留首个已提交快照，旧消息不覆盖。普通RR快照不会成为最终依据。
- 提交前重新读取完整当前行并转换为ES快照，提交后回调只发送，不再查询旧MyBatis会话。局部事件不会把名称、地址等未携带字段清空；回滚不执行这个增量发送。

## ES写入

单条与重建批量均用Painless scripted upsert，在ES里原子比较_source.eventTimestamp。更早的写入no-op，相同版本允许用同一权威行修复，新文档可upsert，带版本文档不被无版本旧数据降级。并发更新冲突最多重试3次；重建返回的是提交条数，包含旧版本no-op，不是实际修改数。

ES写入仍best-effort。MySQL提交后进程崩溃、ES持续不可用仍可能留下缺失/陈旧副本，本轮没有新增持久ES重试队列。消费记录仅证明MySQL业务处理，不证明ES成功；数量一致也不证明字段一致。

## 部署要求

**本轮仅准备迁移，没有执行业务库DDL。新版搜索服务不能直接部署到秒精度旧库。**

1. 停止搜索消费者与读模型/索引重建，排空旧请求，按环境备份。
2. 单独执行 `sql/merged/66-search-event-precision.sql`，只针对llmall-search的event_time升为DATETIME(3)。它不涉及64/65资金协议，不要求执行资金脚本。
3. 确保所有搜索写入实例升级，恢复服务后验证启动guard和增量同步。旧实例无条件写ES/秒截断仍可能破坏新协议。

新安装同样先完成40/41等既有搜索结构，再执行66。重复执行ALTER可保持同一目标结构，但DDL锁定/耗时取决于实际表大小。本轮只在随机私有库执行了脚本中严格匹配的ALTER部分，跳过USE业务库语句；并验证秒精度被拒绝、升级后通过。

## 仍然保留的限制

- occurredAt不是源端单调序列。源端shopId:毫秒的bizId仍可能碰撞，时钟回拨或同毫秒事件无法确定真实因果顺序。本轮只定义同时间首个快照胜出，不宣称解决了源端版本生成问题。
- 各搜索实例必须保持相同时区配置；沿用既有DATETIME与epoch转换约定，没有把历史本地时间改为UTC。旧秒精度数据无法恢复已丢失的毫秒。
- 全量“读模型重建”没有来自门店的可信源版本，会用当前时间标记快照。应在暂停增量、排空请求后受控执行；本轮不保证它与在线变更并发时正确，也不把增量回滚保护扩展成所有重建路径的原子性承诺。
- 比较版本不等于MySQL/ES跨系统事务，也不等于消息一定投递成功。延续既有MQ和消费记录机制，未新增Rabbit故障演练或DLQ实现。

## 证据

真实MySQL/ES原7项测试为6断言失败和1首次创建死锁错误；修复后最终9项通过：同秒毫秒、新旧并发快照、并发首次创建、同版本冲突、回滚不发送ES、成功提交/局部字段/迟到修复的整条服务链路、ES单条/批量旧写no-op及新建、私有ALTER与启动闸门。未降低时间/版本阈值，未写业务库或shop_search索引。

默认测试另覆盖缺失时间、初始化/当前读顺序、同版本、局部旧格式和guard先于生命周期。日志/私有schema/index见 `D:/codex/llmall-search-sync-20261029/`。真实组件测试标记integration，显式运行SearchSyncIntegrationTest并设置LLMALL_TEST_DB_PASSWORD、全新LLMALL_SYNC_TEST_OUTPUT目录。

本轮未部署，不宣称线上已经修好；未做HTTP或吞吐压测，不写性能提升百分比。最终分析和面试手册仍留到整体完工后分别更新。
