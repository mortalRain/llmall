# 登录检查服务出故障时，网关如何处理

可以把Redis里的黑名单和改密时间看成“作废名单”。JWT签名正确，只能证明凭证确实由系统签发，不能证明它后来没有被注销。

以前：查不到作废名单时先放行。这可能让已注销、已改密的旧凭证在故障期间重新得到登录身份。

现在：需要登录才能访问的接口先暂停，返回503和“登录状态暂时无法确认，请稍后重试”；公开的搜索、列表等仍能匿名浏览，但不附带无法确认的用户身份。旧凭证续签时，也必须先检查通过，才能发出新的登录凭证。

## 具体规则

| 情况 | 网关行为 |
|---|---|
| 有效签名，黑名单和改密水位均检查通过 | 继续转发，附带可信用户身份 |
| 明确已注销、改密失效、非法/过期令牌无法刷新 | 保留原401与x-auth-error原因码 |
| Redis连接/命令异常或改密水位格式损坏 | 受保护接口及刷新返回503，不转发、不签新token |
| 公开路由无法确认可选登录身份 | 只匿名转发，客户端伪造的身份/服务凭据头仍剥离 |
| 黑名单脚本无结果或非1结果 | 不采信身份；受保护接口401，公开路由匿名 |
| 下游业务处理报错 | 原样传播，不把业务故障误报成鉴权503，也不重放请求 |

503表示暂时检查不了，401才表示凭证有问题。本次直接返回503不会进入现有前端http.ts的401刷新/清凭据分支。没有新增x-auth-error原因码，也没有改变正常登录凭证格式。

## 实现与代价

`AuthGlobalFilter`用Mono.defer包住三个Redis检查，覆盖创建查询时的同步异常及订阅后的异步异常，统一转换为私有AuthStateUnavailable。受保护流程仅处理这类异常为503；公开流程仅处理这类异常为匿名。错误转换发生在状态读取内部，避免把后续业务异常也吞掉或再执行一遍。

公开路由的可选身份、旧凭证续签增加现有改密水位检查。确认身份需要多一次Redis GET，换取改密后旧身份不再被这些分支忽略。无token的匿名浏览不增加Redis调用。沿用既有authDegrade指标和reason标签；故障日志不打印token、水位原值或凭据。

取舍是：Redis不可用期间，需要登录的读写接口都暂时不可用，而不是带着无法确认的身份继续执行。公开浏览仍能进行。没有增加新中间件、持久表或复杂会话业务。

## 验证与边界

新增AuthStateFailureTest：故障时拒绝受保护读写、坏水位、同步Redis异常、公开匿名与伪造头剥离、公开身份遵守改密、刷新故障不签token、刷新遵守改密、健康access/refresh、下游不重放，以及空/异常脚本结果。旧实现最初12项中10项断言失败，修复后通过；随后补充脚本结果用例。

测试使用JWT解析和Redis替身来准确制造分支，已有AuthGlobalFilterTest继续使用真实RSA签名验证正常行为。本轮不启动容器、不制造实际Redis停机、不部署业务服务，因此不把它描述为线上故障演练。

这次修复的是“检查失败仍放行”。尚未解决Redis重启后撤销数据丢失、注销与续签并发的跨操作原子性；原有无iat旧令牌兼容仍保留。不能据此宣称整个鉴权系统已没有风险。历史文档中的fail-open演练记录反映旧行为，不是当前策略说明。最终完整分析和面试手册仍待整体完工后分别更新。
