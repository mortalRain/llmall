# 凭据历史核对与更正（2026-10-17）

> 本文档记录三件事：① 核验凭据历史暴露面的**正确测法**；② 上一版报告**两处数字的更正**；
> ③ 更正后的实测清单。
>
> **本文不写任何凭据明文**：一律用「长度 + SHA256 前 6 位」标识值（相当于指纹），
> 需要判定"是不是同一个值"时比对指纹即可。

---

## 一、方法论（本轮起每轮适用）

凡用 `-S` 核验凭据暴露面，**取值与搜索必须在同一管道内完成，值不得落到文本上**：

```bash
V=$(git show <commit>:<path> | sed -n 's/^KEY=//p')     # 从仓库取值，不进任何中间文件
printf '%s' "$V" | sha256sum | cut -c1-6                # 用指纹确认"取到的确实是这个值"
git log --all -S"$V" --oneline | wc -l                   # 值命中：该值在历史中出现过的提交数
git log --all -S"$V" --format='%h %s' | tail -1          # 首次进入的提交（最早的）
```

三条硬规矩：

1. **报告层脱敏只能作用于输出**（打印时掩码）；**绝不能作用于输入** —— 把掩码后的串喂给 `-S`
   会得到 0 命中，而这个 0 是假的。
2. **不要用外部给定的字面量代替"从仓库取值"**。外部转述、手抄、二次编辑过的值都可能与仓库不符；
   一旦不符，`-S` 返回 0 且**不会报错**，很容易被误读成"历史里没有"。
3. **两个口径不许混用**：
   - **值命中** = `-S"<裸值>"` → 该值在整个历史中出现过多少提交（**真正的暴露面**）；
   - **行形态命中** = `-S"KEY=<值>"` / `-S"key: <值>"` → 只反映"那一行被增删过几次"，
     **既会漏**（同一值出现在注释、文档、其它文件里时不计数），**也会偏**（行格式改一下就断开）。

**短数字值的已知噪声**：≤4 位纯数字（如三位口令）用裸值搜索没有判别力 ——
它会被订单号、行号、bcrypt 哈希片段等其它数字串命中，条数偏大。这类值以"行形态"为辅，
并在结论里注明噪声；**不要**用它的裸值命中数去和 6 位以上的值横向比较。

## 二、更正记录（保留原文，不删改既有结论）

| # | 原文（上一版报告，2026-10-17） | 实测 | 采用哪个 |
|---|---|---|---|

### 根因（一句话）

**用了一个外部给定、未与仓库对账的字面量去搜，并把"某个字符串 0 命中"误当成了"凭据值不在历史里"。**

补充说明（对上一版"输入层脱敏"这一猜测的回应）：
该次命令是把明文原样交给 git 的 —— 实测 `git log --all -S'690604'` 的字面量就是 `690604`，
不含任何掩码字符；所以**不是**脱敏层错位，而是**取值来源错了**（用了外部字面量而非仓库取值）。
这两者的区别很重要：前者是"打印时手滑"，后者是"证据链起点就不对"，**后者更严重**，
也正是本轮方法论第 2 条要堵的口子。

### 落盘情况

- 上一版「0 命中」这个结论**从未写进任何 `docs/` 或 `README`**：
  `git grep '690604' $(git rev-list --all)` 在**历史与工作树**里都无匹配；
  在 `*.md` 里检索"0 命中/零命中/不含该值"命中的都是**其它话题**（如"全仓 `server.shutdown` 零命中"、"取值冲突 0"），
  与凭据无关。**该结论此前只存在于对话中**，因此本轮以本文档 + 报告显式更正即可。

## 四、对"方案 B"的影响：理由更新，结论不变

**结论不变：不重写历史，改为"声明 + 强制轮换"。**

理由按本轮实测**更新**（比原来的"测得 0"更成立，不是更弱）：

1. **历史已确认含明文**（Redis 口令值命中 15 个提交、首次即根提交；另有 4 类凭据同样在根提交进入），
   所以"历史是干净的"这个前提根本不存在，任何基于它的判断都不成立。
2. **重写无法消除"已泄露"这件事**：知道这些值的人与系统不会因为仓库哈希变了就忘掉。
3. **对公开仓库的 fork / 缓存无效**：fork 仍持有旧对象，GitHub 的 commit 页与第三方镜像缓存也不会立即消失。
4. 代价照旧：48 个提交 hash 全变、tag `llmall-v1.0.0` 需重打、协作者需重新 clone。

因此选择 **声明（README 10.1）+ 强制轮换（六类凭据清单）**，而不是改写历史。
**触发条件**：若将来确认这套栈曾部署到本机以外、或存在真实可用的线上实例，再评估"重写 + 全面轮换"的组合动作。
