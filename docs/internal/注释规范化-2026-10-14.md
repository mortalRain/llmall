## 2. 验收方法：去注释 token 指纹

「只改注释」这句话不能靠人工核对 240 个文件来担保，因此建立了三道闸门。

### 2.1 Java：`CommentFingerprint`

用状态机扫描源码并剔除注释，对每个文件算两个指纹：

- **FP1（token 流）**：保留全部代码字符、压缩连续空白后取 SHA-256。它对换行与缩进不敏感 —— 相同即代表「代码语义逐 token 未变」。
- **FP2（代码行序列）**：剔除注释后逐行 `trimEnd`、丢弃空行后取 SHA-256。它对格式敏感 —— 相同即代表「连换行与书写形态都没动」。

**扫描器必须处理的三类陷阱**（按行正则删注释会在这里出错）：

| 陷阱 | 例子 |
|---|---|
| 字符串里的注释符号 | `String url = "http://a/b//c";` |
| 转义引号 | `"he said \"hi\" // not a comment"` |
| 字符字面量里的斜杠 | `char slash = '/';` |

块注释内部保留换行符，使剔除后的行号与原文件对齐，便于定位差异。

### 2.2 YAML：`YamlFingerprint`

与 Java 同构，但注释规则更需小心：`#` 只有在行首（含前置空白）或前面是空白时才开始注释，出现在引号内的 `#` 是普通字符 —— 例如 `password: "a#b"`。块标量（`key: |` / `key: >`）内部全部是字面量，本仓库当前无此类写法；工具一旦检出会报「需人工复核」而不是给出通过结论。

### 2.3 内容质量闸门：`lint-comments.ps1`

指纹只能证明「没改代码」，证明不了「该删的删干净了」。该闸门按 11 条规则扫描全部注释：

```
HTML标签 / 历史叙述 / 实测叙述 / 口语化 / 装饰横幅 / 粗体标记 / 待办标记
审计标签 / 迁移叙述 / 变更叙述 / 模板残留
```

**闸门本身的两个教训**（都来自实测）：

1. **带误报的闸门比没有闸门更危险** —— 它会诱导出错误的「修复」。初版把「供**本次**请求的日志使用」「1=**新增了**一条」这类正常中文判成违规，收紧后才可用。
2. **必须区分 Markdown 强调与代码通配符**：`/**`（JavaDoc 起始符）、`/items/**`（AntPathMatcher glob）、`138****1234`（手机号掩码）都不是 `**粗体**`。判据需要 `(?<!/)...(?!/)` 守卫。

### 2.4 正反例自测

工具在使用前用一对「代码完全相同、只有注释不同」的样例验证过：带陷阱注释的版本与无注释版本的 FP1/FP2 **完全一致**；而把 `int x = 1;` 改成 `int x = 42;` 会被 FP1 抓出并以退出码 1 失败。

## 3. 内容取舍原则

### 删除

1. 所有 HTML 标签（`<h3>`/`<p>`/`<ul>`/`<li>`/`<b>`/`<pre>` …）与 Markdown 强调标记。
2. 口语化表达、讲故事式背景、历史叙述（「改前是…」「原实现…」「初版…」「实测发现…」）—— 这类信息属于 git 的职责。
3. 代码本身能看懂的逻辑：普通 CRUD、getter/setter、显而易见的赋值。
4. **相邻注解已经说清楚的约束**：`@Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")` 上方再写一条「手机号：11 位，1 开头且第二位 3-9」纯属把注解翻译成中文。
5. **可配置项的值**：`llmall.jwt.tokenTTL` 能被 yaml 覆盖，写「（30 分钟）」会在配置变更后变成一条**错误的注释**；应写不会漂移的表述或用 `{@code ...}` 指路。不变量则相反 —— 金额单位「分」、状态字典值这类稳定事实必须写。
6. 装饰性分隔线、重复表述（同一口径在类/方法/行内说了多遍）。

### 保留

只保留四类：**设计决策**、**隐藏坑点**、**边界约束**（单位/取值范围/时序要求/幂等键口径）、**业务注意事项**。重要提醒统一用 `【注意】` 前缀。

### 更正（唯一允许「改写」的情形）

**类注释与代码事实矛盾时必须更正** —— 错误的注释比没有注释更糟。已知实例：一批 PO/VO 由 MyBatis-Plus 生成器产出，带着 `@author`/`@since` 模板签名，而类注释写的是**别的表**的名字（`Cart`（`@TableName("cart")`）写成「订单详情表」，同一错误也出现在 `CartVO` 上）。更正依据必须来自文件内可见信息（`@TableName`/类名/字段），不得臆造。

## 4. 指纹闸门实际拦下的问题

自动化闸门的价值由它拦下的真实损伤体现。执行过程中，**有 4 处改动会被 FP1/FP2 拦下并还原**：

| 类型 | 具体损伤 | 后果 |
|---|---|---|
| 误删字段声明行 | `ShopSearchReconcileTask.consecutiveUnknownRounds` | 编译错误（尚可发现） |
| 注释行与代码行被合并 | `BalanceFlow flow = ...` 与上一行注释粘连 | **编译通过、语义可能已变** |
| 误删行尾换行 | `VoucherServiceImpl` 三处、`OrderServiceImpl` 两处 | 同上 |
| 字段行被吞 | `MessageLog.retryCount` | 编译错误 |

第 2、3 类是最危险的：编译完全通过，代码语义却可能已经变化。

## 5. 阶段三：业务代码规范精简

对「魔法值、重复参数校验、冗余临时变量、无用空判断、无引用私有方法」做了全项目扫描，**可动的手术面比预期小**（项目此前已过 8 轮审计）：

### 已做（值一字未改，编译通过）

| 文件 | 改动 |
|---|---|
| `CommonExceptionAdvice` | `300` → `MAX_ROOT_MESSAGE_LENGTH` 常量（原本字面量重复出现两次） |
| `SentinelRuleConfig` | 抽出 `DEGRADE_EXCEPTION_RATIO` / `DEGRADE_TIME_WINDOW_SECONDS` / `DEGRADE_MIN_REQUEST_AMOUNT`，并**修掉一处日志漂移**：日志字符串里硬编码「最小请求数 10」，而实际值来自 `setMinRequestAmount(10)`，改一处日志就会说谎 |
| `CartServiceImpl` | `10` → `DEFAULT_MAX_ENTRIES` 常量 |

### 审计后**未做**（与「业务逻辑、功能、入参出参完全不变」冲突）

| 项 | 为什么不做 |
|---|---|
| 「统一异常抛出」：17 处 `IllegalStateException`/`RuntimeException` | 这些异常在 `CommonExceptionAdvice` 里走**兜底映射 500**，而 `CommonException` 系映射 400。它们全是「消息体序列化失败」「未注册的消息类型」「ES 检索失败」这类内部/基础设施错误 —— 统一成业务异常会把 500 变成 400、**掩盖真实故障** |
| `CartVO` 的 `status = 1` / `stock = 10` 默认值 | 响应 VO 上的默认值意味着商品未加载时前端会看到「库存 10」，更像缺陷；但改它就是行为变更 |
| 三个服务的 `MessageLogServiceImpl` 重复（194/214/191 行） | 真实重复，但属结构性重构 |

其余扫描结果：无用空判断 0 命中、无引用私有方法 0 个、方法内重复参数校验未发现。

## 6. 复现方式

> **【路径变更】** 本节记录的是 2026-10-14 那轮当时的工具位置（仓库外）。
> 耐久工具集与现行基线后来已迁入仓库的 `gates/`，复跑请按 `gates/README.md`；
> 下面这张表里的工具名与用途仍然有效，只是路径前缀由 `gates/\` 改为 `gates\`。

校验工具与规范文档位于仓库外的 `gates/\`（该目录被 `.gitignore` 排除）：

| 文件 | 用途 |
|---|---|
| `CommentFingerprint.java` | Java 去注释指纹（`stats`/`snapshot`/`verify`/`check` 四种模式） |
| `YamlFingerprint.java` | YAML 去注释指纹 |
| `lint-comments.ps1` | 注释内容质量闸门（11 条规则） |
| `lint-scripts.ps1` | 非 Java/YAML 文件语法闸门（PowerShell AST / JSON / XML） |
| `check.ps1` / `yaml-check.ps1` | 单文件校验入口 |
| `accept.ps1` | 一键跑完全部闸门 + 13 模块编译 |

基线指纹：`baseline/java.baseline.txt`（优化前）、`baseline/java.post-phase3.txt`（阶段三后）。

```powershell
# 一键验收（含编译）
pwsh -File gates/\accept.ps1

# 只看注释内容质量
pwsh -File gates/\lint-comments.ps1
```
