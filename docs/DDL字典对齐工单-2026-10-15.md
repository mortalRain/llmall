## 二、执行方式（重要：列定义必须复制，不能手写）

`ALTER TABLE ... MODIFY COLUMN` **要求写出完整列定义**，只写 COMMENT 会丢掉类型/可空性/默认值。
因此每一步都按下面的流程做，**不要凭记忆或凭本工单写类型**：

```sql
-- 1) 先取当前定义（复制输出里的列定义整段）
SHOW CREATE TABLE `llmall-item`.`stock_flow`;

-- 2) 在复制出来的列定义里**只改 COMMENT 部分**，其余逐字保留
ALTER TABLE `llmall-item`.`stock_flow`
  MODIFY COLUMN `status` TINYINT NOT NULL DEFAULT 1 COMMENT '1 有效（回补以新增正数流水表达，不存在 2 已回滚）';

-- 3) 复核
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_DEFAULT, COLUMN_COMMENT
  FROM information_schema.COLUMNS
 WHERE TABLE_SCHEMA='llmall-item' AND TABLE_NAME='stock_flow' AND COLUMN_NAME='status';
```

其余 6 处按同一模式执行（表/列/目标注释见第一节表格）。

**幂等性**：`MODIFY COLUMN ... COMMENT` 可重复执行，第二次结果相同，不会报错。
**回滚**：把 COMMENT 改回第一节"当前注释"列的原文即可（`MODIFY` 本身不触碰数据）。
**风险等级**：整体**低**（只动 COMMENT，不动类型/可空性/默认值，也不动数据）；
唯一的中风险点是 **D-06**（注释语义跨了两套状态机），建议单独执行并复核。
