## 当前构建私有联调做了什么

1. 只读业务库表元数据，用 CREATE TABLE LIKE 克隆 **空表结构**到随机 `llmall_smoke_bd512eb8ee_*` 九个私有库；不复制用户/订单/余额等原业务记录。
2. 64/65/66 中所有目标库严格改为私有映射，按顺序执行成功，保留迁移前置守卫；原业务库未迁移。
3. 插入合成账号、测试余额、门店/套餐和普通付费券；两个口令分别 BCrypt，非默认强登录口令；生成一份私有 JWT 密钥供用户服务与网关共同读取。
4. 启动当前 package 构建的 user/item/shop/promotion/trade/pay/cart/content/gateway 九个真实 Boot 进程：每个 `Xmx128MiB`、metaspace128MiB、活动处理器2；Tomcat最多4线程、数据库池3连接。监听仅127.0.0.1。
5. 浏览器真实登录→个人中心修改支付口令→清本地会话/回登录页；网关拒绝旧 JWT，再用登录口令重新登录。验证码走 local provider，未发送商业短信。
6. 100分购买200分面额普通券，查询 ISSUED；1000分套餐用券后800分，下单同令牌回放同一订单；建支付单、余额支付、查询订单已支付；再次支付拒绝；另一账号读取该订单/券拒绝。
7. 独立查库：余额 **100000→99100分**、两条扣款流水、一个 SUCCEEDED 支付尝试。不是只看 HTTP200。
8. 私有 Redis/Sentinel 使用 AOF everysec + noeviction，验证配置及容器 restart 后标记仍在。只证明本次普通重启持久化，不证明断电零丢失/重建无卷恢复/跨主机 HA。
9. 联调结束，九个应用及私有 UI 进程退出，私有 Redis 和 Rabbit 停止；既有 MySQL 保持运行。最后抽样空闲内存约5303MiB；不是全程峰值统计。

## Redis评估结论

共享 Redis 有缓存和安全控制状态，继续用 allkeys-lru 且关闭持久化会让撤销/锁定状态存在驱逐和重启风险。最低成本方向为 **持久卷+AOF everysec+noeviction+容量告警**；代价是内存满时写入失败，需让调用方明确失败/降级，缓存容量与安全状态后续可分实例。

本批在私有环境验证配置与普通重启，不自动更换现有业务 Redis、重建容器或宣称 HA。现有部署默认值、撤销写入 best-effort、持久恢复故障窗口仍记为上线前问题。若需改密后硬性撤销，必须另做持久用户版本或撤销恢复，不能用“有Redis”作证明。
