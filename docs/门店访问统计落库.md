# 门店访问统计落库（shop_stat）

> 补完一个「DDL 与种子数据都在、就是没有代码」的缺口：门店访问 UV/PV 此前只在 Redis 里活 2 天，
> 历史数据会永久丢失。

---

## 1. 为什么需要它

访问统计的运行时实现一直都在 Redis：

| 指标 | 结构 | key | 说明 |
|---|---|---|---|
| UV | HyperLogLog | `uv:shop:{日期}:{门店id}` | 估算独立访客数，标准误差 0.81%，只占 12KB |
| PV | 计数器 | `pv:shop:{日期}:{门店id}` | 当日访问次数 |

两者的 key 都**按天新建**，且只保留 `llmall.shop.cache.uv-ttl-days` 天（默认 **2 天**）。

**问题**：两天后 key 过期，"上周三有多少人访问过这家门店"这个数据就永久消失了。

`shop_stat` 表（`sql/merged/10-shop.sql`）早就建好了，DDL 注释也写明了意图
（"UV 用 Redis HyperLogLog 估算，每日落库一份"），`51-seed-more-data.sql` 还插了演示数据 ——
但**全项目没有任何一处写它**。本功能就是把这个承诺补上。

---

## 2. 实现

| 文件 | 作用 |
|---|---|
| `ShopStat`（PO） | 映射 `shop_stat` |
| `ShopStatMapper` | 一条 `INSERT ... ON DUPLICATE KEY UPDATE`，靠唯一键 `uk_shop_date(shop_id, stat_date)` 幂等 |
| `ShopStatRollupTask` | 每日把指定日期的 UV/PV 从 Redis 落到表 |
| `ShopServiceImpl#recordVisit` | 原有 UV 脚本追加 PV 计数（**同一条 Lua，不增加网络往返**） |
| `ShopController#rollupVisitStat` | 运维手动触发入口，受 `llmall.maintenance.enabled` 开关约束 |

### 关键设计点

1. **PV 与 UV 一起采集**。表里有 `pv` 列，如果只落 UV，每一行都会是「访问次数 0、访问人数 123」
   这种自相矛盾的数据。PV 的 `INCR` 加在**已有的那条 Lua 脚本**里，往返次数不变，
   `PEXPIRE ... NX` 的 TTL 策略也照旧。
2. **脚本返回值不变**。原脚本返回 UV key 的 `PEXPIRE` 结果，供调用方判断是否首次创建；
   新脚本用 `local ttl = ...` 保存后仍在最后返回它，调用方逻辑无需改动。
3. **定时用 cron 而非 fixedDelay**。`fixedDelay` 从应用启动时刻起算，会把"统计日期"错开成运行时间点；
   cron 固定在每天 00:10（`llmall.shop.stat.rollup-cron` 可覆盖），错开 10 分钟是为了让跨零点的访问先把 key 写完。
4. **幂等靠唯一键，不靠"先查后插"**。任务重跑、多实例同时触发、手动触发与定时撞车，
   都只会覆盖成同一份值。
5. **当天没有访问的门店不落库**（写了会用 0 覆盖掉可能已存在的历史行）。
6. **逐门店取数而非 SCAN**：门店量级是"百"，每天一轮的 N 次 `PFCOUNT`/`GET` 完全可以接受；
   `SCAN uv:shop:{date}:*` 会做大范围键扫描，代价更高且结果是弱一致的。

## 3. 怎么验证

### 手动触发（无需等到凌晨）

```bash
# 1) 造点访问量
curl -X POST http://localhost:8080/shops/1/visit -H "authorization: <登录后的 access token>"
curl -X POST http://localhost:8080/shops/1/visit -H "authorization: <登录后的 access token>"

# 2) 确认 Redis 侧写进去了（UV 是 HLL，PV 是计数器）
redis-cli -a 123456 PFCOUNT "uv:shop:$(date +%F):1"
redis-cli -a 123456 GET     "pv:shop:$(date +%F):1"

# 3) 落当天的数据（运维入口）
curl -X POST "http://localhost:8080/shops/stat/rollup?date=$(date +%F)" \
     -H "authorization: <access token>"
# 返回：实际写入的门店数

# 4) 查库
mysql -uroot -p123 -e "SELECT * FROM \`llmall-shop\`.shop_stat WHERE stat_date = CURDATE()"
```

**注意**：`POST /shops/{id}/visit` 需要登录（网关白名单只放行单段读接口）；
`POST /shops/stat/rollup` 受 `llmall.maintenance.enabled` 控制（默认 true），关闭时返回 403。

### 定时触发

默认每天 00:10 落前一天的数据。日志关键字：`门店访问统计落库完成: date=..., 门店总数=..., 有访问并落库=...`

## 4. 边界与已知取舍

- **匿名流量不做去重**：未登录访客统一记为 `guest`，所以 UV 口径是"登录用户数 + 匿名 1"。
  要精确统计匿名 UV 需按 IP/session 生成随机标识，本项目不追求该精度（原有实现即如此，本次未改动）。
- **UV 是估算值**：HyperLogLog 标准误差 0.81%，不适合当精确账目用。
- **本表是历史留档**：实时值查 Redis（`GET /shops/{id}/uv` 是今日 UV），不要查库。
- **多实例部署**时每个实例各自落库，靠唯一键保证不会重复 —— 与 `ShopSearchReconcileTask` 同一口径。
