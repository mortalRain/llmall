# 商城、购物车、门店收藏与评价

> 本文记录 2026-10-26 补齐的「商城侧 + 门店互动」：后端门店收藏、评价种子，前端商城 / 商品详情 /
> 购物车 / 收藏 / 门店评价，以及结算页的购物车多商品扩展。
>
> 前置口径：演示账号 `Jack/123456`、`Rose/123456`，支付口令 `888888`；网关 `http://localhost:8080`，
> 前端 `http://localhost:5173`。

## 一、后端接口

### 1. 门店收藏（均需登录）

`userId` 一律取 `UserContext`，不从请求体/query 接收；四个路径都是多段路径，不在网关只读白名单
`/shops/*` 内，未登录在网关即 401。

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/shops/{id}/favorite` | 收藏门店，**幂等**；重复收藏返回 200 |
| `DELETE` | `/shops/{id}/favorite` | 取消收藏，**幂等**；未收藏也返回 200 |
| `GET` | `/shops/{id}/favorite` | 当前用户是否已收藏，返回 `true/false` |
| `GET` | `/shops/my/favorites` | 我的收藏，返回 `List<ShopDTO>`，按收藏时间倒序 |

- 收藏一个不存在的门店返回 400（`门店不存在: {id}`），避免留下永远渲染不出来的孤儿行。
- 列表用 `shop_favorite` 的关系行查出门店 id，再走门店域自己的 `queryByIds` 取最新展示字段；
  已物理删除的门店行直接跳过。
- 落库脚本：[`sql/merged/34-shop-favorite.sql`](../sql/merged/34-shop-favorite.sql)。
  `UNIQUE uk_user_shop(user_id, shop_id)` 是并发重复收藏的最终闸门，`KEY idx_shop(shop_id)` 支撑按门店清理。
- `shop` 表/实体**没有** `favorite` 统计字段，本次只做关系表，没有编造或维护计数列。

### 2. 评价种子

- 脚本：[`sql/merged/35-review-seed.sql`](../sql/merged/35-review-seed.sql)。
- 数量：门店 **1 / 3 / 4 / 10 / 11** 各 **6 条**，共 **30 条**。
- 字段：`score` 4~5、`liked`/`comments` 小数值、`status=1`、`create_time` 近 30 天、
  `content` 为 20~80 字真实中文评价；`user_id` 使用演示库已有用户 1/2/3。
- 幂等：`INSERT ... SELECT` + `(shop_id, user_id, title) NOT EXISTS`，重复执行不新增、不更新已有行，
  不写死主键 id。
- 顺序：`demo.ps1` 把 34 放在 32 之后（应用发布前建表），把 35 放在 50/51 四步演示数据之后，
  避免被后续 seed 的 `DELETE` 区间清掉；`sql/merged/README.md` 的执行清单同步更新。
- `GET /blogs/shop/10?page=1&size=10` 返回 `PageDTO<Blog>`：`total/pages/list`，`list` 项含
  `shopId/userId/title/content/score/liked/comments/status/createTime`，与前端按分页结构渲染一致。
  **字段缺口**：`blog` 只有 `user_id`，没有作者昵称/头像字段，内容域也没有按 id 批量查用户资料的接口；
  前端以「同城用户 {userId} + 首字头像」展示，未伪造昵称。

## 二、前端页面

| 路由 | 文件 | 能力 |
|---|---|---|
| `/mall` | `frontend/src/views/Mall.vue` | 关键词 `key`、分类 `/items/categories`、价格区间（元→分）、`pageNo/pageSize` 分页、加购、店铺名回填 |
| `/item/:id` | `ItemDetail.vue` | 图片/价格/库存/销量/规格、所属门店跳转、加购、立即购买（`itemId+num`） |
| `/cart` | `Cart.vue` | 图/名/规格/单价/数量/小计、`PUT /carts` 改数量、`DELETE /carts/{id}`、单选/全选、合计、去结算 |
| `/favorites` | `Favorites.vue` | `GET /shops/my/favorites`、取消收藏、进门店 |
| `/shops/:id` | `ShopDetail.vue` | 新增收藏按钮（`GET/POST/DELETE`，已收藏高亮）与评价区分页（`GET /blogs/shop/{shopId}`） |
| `/checkout` | `Checkout.vue` | 兼容立即购买单商品；购物车多商品从 `sessionStorage.llmall.checkout.lines` 读取，`POST /orders` 的 `details` 传多行 |
| `/profile` | `Profile.vue` | 新增「我的收藏 / 购物车」入口 |

顶部导航顺序：动态 / **商城** / 门店 / **购物车** / **我的收藏** / 订单 / 我的 / 核销台 / 员工管理
（后两项仍按员工角色展示，未改核销/员工/订单既有逻辑）。

### 结算页兼容策略

- **立即购买**：`/checkout?itemId={id}&num={n}`，只生成 1 行，和改造前行为一致。
- **购物车结算**：`Cart.vue` 把选中的 `{cartId,itemId,num}` 写入 sessionStorage；
  `Checkout.vue` 读取后按 `itemId` 批量拉最新商品（价格/库存），读后清空，避免刷新重复结算。
- 两类入口最终都走同一个 `details: [{itemId,num}, ...]`；地址、优惠券、余额支付三步流程未改。
- 多门店商品合并结算时，只允许无门店限制的券；本店券仅在"全部商品同属一家门店"时出现。
- 订单创建成功后，交易域发 `order.create` 事件，购物车服务按 `userId + itemIds` 自动清理条目。

## 五、未验证项 / 已知边界

1. **作者昵称/头像**：见上文，`blog` 无作者展示字段，评价区显示「同城用户 {userId}」+ 首字头像；
   要显示真实昵称需新增用户域批量资料接口并让内容域回填，本次未扩大改动面。
2. **门店收藏计数**：`shop` 表没有 `favorite` 字段，未新增/未维护收藏数；列表只返回门店 DTO。
3. **分页参数命名**：需求写的是 `page/size`，实际后端 `/items/page` 使用 `pageNo/pageSize`
   （`ItemPageQuery extends PageQuery`），前端按后端真实契约调用；门店 `/shops/page` 仍是 `page/size`。
4. **评价写入 UI**：本次只做评价展示与种子，没有新增"写评价"页面；发布评价仍走既有 `POST /blogs`。
5. **多门店优惠券**：购物车含多门店商品时门店券不可用，仅无门店限制券可选；这是现有券模型
   （`voucher.shop_id` 单值）的边界，未改营销域。
6. **生产数据**：35 号脚本是演示/冒烟数据，生产库不得执行；34 号是纯结构脚本，可与应用同批发布。
7. **本地部署方式**：本轮为快速验证把新 jar `docker cp` 进现有 `llmall-shop-service` 容器并重启；
   正式重建仍应按 `README §4.4` 重新 `docker build` + compose，否则容器重建会回到旧镜像。
8. 未覆盖真实浏览器的移动端手工回归；仅按既有 1440px 断点检查了新增页面的桌面/窄屏样式。
