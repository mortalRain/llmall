## 1. 专项一：资金安全与幂等

### 1.1 `1,500 次完整闭环（下单 / 支付单 / 支付各 1,500）`

- **证据（A）**：`benchmark/README.md:207-219`
  - `50 线程 × 30 轮 = 1,500 次完整闭环；实测 4,502 请求 / 61 秒 / 错误率 0%`
  - 表：`POST /orders` 1,500 次、`POST /pay-orders` 1,500 次、`POST /pay-orders/{id}` 1,500 次
- **原始压测脚本**：`benchmark/write-order-pay-multi.jmx`
- **复跑**：按 `benchmark/README.md` §4 的 JMeter 命令；`logs/task1/`、`logs/p01-2026-10-26/` 有历史 `.jtl`
- **注意**：实测是 50 线程；100 并发可写为设计目标（本机资源上限），或补 100 的 `.jtl`；`1,500` 是总次数，不是并发数。

### 1.2 `余额减少 38,400,000 分，与支付次数一致`

- **证据（A）**：`benchmark/README.md:219`
  - `余额 60,000,000 → 21,600,000 = 38,400,000 分；38,400,000 ÷ 25,600 = 1,500.0`
- **证据（B）**：`llmall-user-service/.../UserServiceImpl` 的余额扣减与流水写入；`llmall-pay-service/.../PayOrderServiceImpl`
- **注意**：简历可写“差额 0”，但不要写“分毫不差”这种情绪词。

### 1.3 `20 线程双击同一支付单，1 成功 + 19 拒绝`

- **证据（A）**：`benchmark/README.md:181、274`
  - `同一张支付单，20 个线程同时 POST /pay-orders/{id}` → `1×200 + 19×400`，余额只减 25,600
- **证据（B）**：`llmall-pay-service/.../PayOrderServiceImpl#tryPayOrderByBalance` 的条件更新 + `uk_biz`
- **注意**：实测 20 线程；100 线程可写为设计目标；幂等由 `uk_biz` 唯一键裁决，结论不随线程数变化。

### 1.4 `Seata AT 对照 +259% 后默认关闭`

- **证据（A）**：`docs/P-03-Seata-AT对照-2026-10-17.md:252`
  - `POST /orders`：AT 开启 `247.7 / 382 / 531 ms`，关闭 `68.9 / 99 / 177 ms`，`+259%`
  - 同文 `:259`：吞吐 `58.5 rps` vs `73.9 rps`（−21%）
- **证据（B）**：`llmall-trade-service/.../OrderServiceImpl` 的 `@GlobalTransactional`；`nacos-config/` 或 `application.yaml` 的 `seata.enabled` 默认 false（开关保留）
- **复跑**：`jmeter -n -t benchmark/write-order-pay-multi.jmx` 只切 `seata.enabled`；详见 P-03 §4
- **注意**：`+259%` 是相对值，绝对值是 **247.7ms**、每笔多 **178.8ms**；不要说成“延迟 259ms”。

### 1.5 `本地消息表 + PENDING / DEDUCTED / UNKNOWN 三态`

- **证据（B）**：
  - `llmall-trade-service/.../OrderServiceImpl`：`messageLogService.record(...)` 与业务同事务
  - `llmall-pay-service/.../enums/PayStatus.java`：`PENDING / DEDUCTED / UNKNOWN`
  - `llmall-pay-service/.../PayOrderServiceImpl`：`claimDeductAttempt`、`markDeductUncertain`
- **证据（C）**：`docs/payment-reliability.md`、`docs/设计决策问答.md` 相关章节
