# 旧付费秒杀入口与异步用户上下文

## 秒杀新请求

旧秒杀通过 token 及消息补偿发券，没有普通付费购买的持久化尝试恢复协议。本次不扩建第二套资金系统：新付费秒杀请求一律拒绝，在查秒杀配置、Redis 预热和收款前返回明确错误。未提供重新开启收款的配置开关。售价负数/超 int 上限同样拒绝；零价和历史 null 售价保留免费流程。

普通购买仍由既有购买账本处理。旧消息的消费、查询和补偿不被这项新请求检查拦截，便于既有任务排空；这不证明历史在途付费消息已完成核对或取消。部署前仍需单独排查，不能将关闭入口写成完整付费秒杀恢复已实现。

## 异步身份

装饰器在提交时捕获用户，在执行时保存执行线程原用户，安装捕获的身份（匿名任务明确清空），最后恢复执行前的身份；执行前为空才移除。异常同样恢复并继续传播。

这同时覆盖普通池线程、嵌套任务和 CallerRunsPolicy 在请求线程执行的路径。恢复动作不再无条件清掉请求线程用户；匿名任务也不会继承池线程意外残留的用户。此处只处理 UserContext，不宣称清理其他 ThreadLocal、MDC 或请求生命周期。

## 验证范围

5 个上下文用例覆盖有用户/匿名、异常、嵌套，以及真实有界线程池饱和后的 CallerRuns。7 个服务边界用例确认付费/非法售价在配置、Redis、余额和消息之前拒绝，免费请求继续到原配置验证；这些不是完整免费秒杀的端到端压测。无容器启停、业务迁移或部署。
