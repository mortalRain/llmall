# 冒烟、压测数据安全

## 当前行为

- `demo.ps1` 冒烟成功或失败均保留业务数据；`-NoCleanup` 仅作旧调用兼容，不再改变保留策略。日志及运行报告说明这一点。
- `scripts/SmokeRollback.java` 保留 `capture` / `verify` 只读能力及旧快照格式。`rollback` 在连库和读取快照前以退出码 2 拒绝。只读 JDBC 模式建议配合 SELECT 专用账号，不能作为数据库权限的替代。
- `sql/cleanup-e2e-data.sql`、`sql/cleanup-bench-data.sql`、`sql/merged/52-fix-orphan-pay-orders.sql` 仅返回 `CLEANUP_DISABLED` 错误，不含删除、直接退款或余额/库存覆盖语句。客户端强制忽略错误也没有后续写语句可执行。

## 为什么不能按水位恢复

id 大于快照上界，只说明行在之后出现，无法证明它属于本轮测试。订单、库存、券、余额流水、资金操作记录、购买记录、Outbox、消费幂等记录和缓存分散在多个域，任务可能仍在重试。删除部分事实或写回余额快照会丢失恢复依据，也可能覆盖其他操作。`client_token` 非空、固定用户 id 区间同样不能证明测试归属。

本批仅关闭这些不安全入口，没有提供完整业务回滚，也不自动修复历史数据。`capture` / `verify` 只比较部分表和列，差异为零不代表资金、消息和跨域状态全部一致；测试产生差异是正常现象。只使用可信的快照文件。

## 如何继续测试

1. 冒烟、写压测使用与业务数据隔离、可丢弃的测试环境，不连接有价值的数据。
2. 测试后保留订单、流水、恢复状态与日志，等待任务收敛并按业务不变量核对。不要删除记录绕过 64/65 迁移守卫。
3. 需要干净基线时，确认目标确实是独立测试环境、停止流量和任务、保存必要证据后，完整重建这一环境。仅重建部分数据库不能视为完整还原。

`demo.ps1 -Reset`、`-Down -Volumes` 原有容器销毁行为未修改，仍可能删除持久数据；本次关闭的是冒烟后的业务行自动清理。不要在共享或有价值环境执行销毁命令。

## 后续精确清理的前提

若确有按批次清理需求，应先引入明确的 fixture/runId，关联完整业务与资金凭据，明确消息排空、恢复任务终态、资金净额、库存/券与缓存影响集，并证明不涉及非测试数据。当前尚未实现这些前提，不增加“强制启用旧清理”的开关。

## 离线回归

在仓库根目录运行 `pwsh -NoProfile -File scripts/tests/cleanup-safety.Tests.ps1`，需要 JDK 11 或更新版本，Windows PowerShell 5.1 同样可执行。测试使用离线 JDBC 替身，不连接真实数据库；SQL 检查验证整个文件只有一条停用错误，未在 MySQL 实机执行。
