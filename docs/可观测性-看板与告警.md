# 可观测性：看板、告警与演练手册

> 目标：把"系统现在健康吗、出问题在哪"变成**一页看板 + 七条告警 + 一次演练**，
> 而不是靠翻日志。本文只描述口径与操作步骤；本轮改造**没有在运行环境执行演练**，
> 演练记录需要你在起完整栈后按第 4 节跑一遍再补数据。

---

## 1. 启动

前置：业务栈已按 `deploy/docker-compose-apps.yml` 起来，`local-life` 网络存在。

```bash
cd D:/dsh/llmall
docker compose -f deploy/docker-compose-observability.yml --profile obs up -d
```

- Prometheus：http://localhost:9090
- Grafana：http://localhost:3000（admin / `GRAFANA_PASSWORD`，默认 admin）

Grafana 已自动注入 Prometheus 数据源与「llmall 运行看板」，无需手工导入。

## 2. 指标口径

| 指标 | 含义 | 来源 |
|---|---|---|
| `http_server_requests_seconds_*` | 各接口 QPS / 延迟 / 状态码 | Spring Boot Actuator + Micrometer 自动埋点 |
| `llmall_auth_degrade_total{reason}` | 鉴权降级次数（blacklist / watermark / token-state） | `AuthGlobalFilter` |
| `llmall_auth_code_failure_total{scene,reason}` | 验证码失败（mismatch / locked / expired） | `UserServiceImpl` |
| `llmall_auth_login_failure_total{reason}` | 登录失败（bad-credential / locked） | `UserServiceImpl` |
| `llmall_pay_deduct_uncertain_total` | 扣款结果未知 | `PayOrderServiceImpl` |
| `llmall_compensation_failure_total{domain,action}` | 补偿失败（退款/回补） | 支付、营销 |
| `llmall_search_fallback_total{reason}` | 检索回落（empty-index / es-error） | `SearchServiceImpl` |
| `llmall_feed_fanout_skipped_total` | Feed 写扩散被阈值跳过 | `FollowServiceImpl` |
| `hikaricp_connections_*` | 连接池活跃/等待 | Actuator 自动埋点 |
| `jvm_memory_used_bytes{area="heap"}` | 堆使用 | Actuator 自动埋点 |

## 3. 告警与处置

| 告警 | 阈值 | 先看什么 | 处置 |
|---|---|---|---|
| `LlmallHighErrorRate` | 5xx > 1%（5 分钟） | 网关与下游 Feign 的 5xx 分布、traceId 日志 | 先止血（回滚/摘流量），再定位 |
| `LlmallHighP99Latency` | P99 > 1s（5 分钟） | 该 uri 的 Hikari pending、下游 Feign 耗时 | 对照历史压测结论判断是池排队还是慢查询 |
| `LlmallAuthDegraded` | 5 分钟内出现降级 | Redis 连通性、`reason` 标签 | 恢复 Redis；窗口内已注销令牌可能仍被放行，必要时强制重新登录 |
| `LlmallLoginBruteForce` | 10 分钟失败 > 20 | 失败集中在一个 username 还是分散 | 分散是撞库，收紧限流；集中是单账号爆破，已自动锁定 |
| `LlmallCompensationFailure` | 10 分钟内 > 0 | 日志里的幂等键（`PAYFAIL:*` / `VOUCHER_REFUND_*`） | 先核对流水确认是否已退，**不要直接重试退款** |
| `LlmallDeductUncertain` | 10 分钟内 > 0 | `pay_order.result_code=UNCERTAIN` | 按幂等键核对余额流水；未知不能当未支付 |
| `LlmallSearchFallbackHigh` | 5 分钟 > 10 | `reason`：empty-index 还是 es-error | 前者重建索引，后者查 ES 健康 |

## 4. 故障演练（待执行）

**演练 A：鉴权降级**
1. 压测 `/users/me`（带有效 access token）保持 10 QPS。
2. 停 Redis 30 秒：`docker stop <redis 容器>`。
3. 预期：请求仍返回 200（fail-open），`llmall_auth_degrade_total{reason="blacklist"}` 抬头，
   `LlmallAuthDegraded` 告警进入 firing，日志出现「【鉴权降级】」。
4. 恢复 Redis，确认指标停止增长、告警恢复；记录降级窗口时长与放行请求数。

**演练 B：补偿失败**
1. 停用户服务，触发一次支付失败补偿。
2. 预期：`llmall_compensation_failure_total{domain="pay"}` +1，告警 firing，日志带幂等键。
3. 恢复后按幂等键手工核对，**确认未退再退**。

**演练 C：检索回落**
1. 停 ES 或清空索引文档（保留索引）。
2. 预期：`llmall_search_fallback_total{reason}` 增长，检索结果仍非空（MySQL 读模型兜底），
   P99 上升但错误率为 0。

> 演练记录模板：时间 / 注入动作 / 观测到的指标与告警 / 用户影响 / 恢复动作 / 后续改进。
> 一次真实演练的价值高于十张看板截图——面试讲"我怎么发现并处理"时用它。

## 5. 边界（不要说过头）

- 目前是 **traceId 贯穿日志 + 指标**，没有接入完整链路追踪后端（OTel/SkyWalking）；跨服务调用靠 `X-Trace-Id` 关联。
- 告警目前只到 Prometheus 规则与 Grafana 面板，**没有接 Alertmanager 的通知渠道**。
- 压测口径仍是单机同测，看板上的 QPS/P99 不可直接对标生产。
