# 员工角色与员工管理（OWNER / MANAGER / STAFF）

> 一句话：核销权继续对所有门店员工开放；在 `shop_staff.role` 上补出三档管理权限，
> 新增门店侧员工管理接口与 `/staff/manage` 页面，并用"最后 OWNER 保护"保证门店不会失去管理员。

## 一、角色模型

| 角色 | 核销 | 查看员工列表 | 新增/删除员工 | 修改角色 | 授予/撤销 OWNER |
|---|:---:|:---:|:---:|:---:|:---:|
| `OWNER` 店主 | ✅ | ✅ | ✅ | ✅ | ✅ |
| `MANAGER` 店长 | ✅ | ✅ | ✅（仅 STAFF/MANAGER） | ✅（仅 STAFF/MANAGER） | ❌ |
| `STAFF` 员工 | ✅ | ❌ | ❌ | ❌ | ❌ |

不变式：

1. **核销判权不变**：`isStaff(shopId, userId)` 只回答"是不是本店员工"，不比较角色；
   交易域 `POST /orders/verify` 仍调用门店域内部接口，任意角色都可核销。
2. **管理权由门店域自己判**：不把"是否管理员"下放给交易域或前端；操作者身份只来自 `UserContext`。
3. **只有 OWNER 能授予/撤销 OWNER**：否则 MANAGER 可以自我提权到 OWNER。
4. **门店至少保留一个 OWNER**：删除或降级最后一个 OWNER 返回 `409`（包括店主删除自己）。
5. **未知/非法 role 按 STAFF 处理（fail-closed）**：存量脏数据不会意外变成管理员；
   请求体里的 role 非法则直接 `400`，不会静默降级。

## 二、接口

所有接口都需要登录；管理接口还要求操作者是该店 OWNER/MANAGER。

### 2.1 我任职的门店与角色

```http
GET /shops/my/staff
→ [{"shopId":"10","role":"OWNER"},{"shopId":"1","role":"OWNER"}]
```

- 旧口径是 `["10","1"]`，前端无法区分角色；现在返回 `{shopId, role}`。
- 前端用它决定：核销台（任意角色）/ 员工管理（仅 OWNER/MANAGER）入口。
- 只是展示开关，不是权限边界。

### 2.2 员工列表

```http
GET /shops/{shopId}/staff
→ [{"userId":"1","role":"OWNER","createTime":"2026-10-26T19:36:21"},
   {"userId":"3","role":"MANAGER","createTime":"2026-10-26T20:08:17"}]
```

- 排序：OWNER → MANAGER → STAFF，同角色按加入顺序。
- 非本店 OWNER/MANAGER（包括本店 STAFF）→ `403 {"code":403,"msg":"仅本店店主/店长可管理员工"}`。

### 2.3 新增员工

```http
POST /shops/{shopId}/staff
{"userId":"2","role":"STAFF"}
```

| 场景 | 响应 |
|---|---|
| OWNER 新增 STAFF/MANAGER/OWNER | `200` |
| MANAGER 新增 STAFF/MANAGER | `200` |
| MANAGER 新增 OWNER | `403 只有店主可以授予店主` |
| 该用户已是本店员工 | `409 该用户已是本店员工` |
| role 不是 OWNER/MANAGER/STAFF | `400 role 取值不合法，只能是 OWNER / MANAGER / STAFF` |
| 非本店 OWNER/MANAGER | `403 仅本店店主/店长可管理员工` |

> 并发窗口由唯一键 `uk_shop_user(shop_id,user_id)` 兜底：撞键翻译成 `409`，不会变成 500。

### 2.4 修改角色

```http
PUT /shops/{shopId}/staff/{userId}
{"role":"MANAGER"}
```

- 需求只列了 GET/POST/DELETE；改角色单独加 `PUT`，避免把 POST 做成"重复则更新"
  （需求明确重复要 409），也避免前端"先删后加"（删最后一个 OWNER 会被拒）。
- MANAGER 不能把任何 OWNER 改成别的角色，也不能把任何人改成 OWNER（403）。
- 把最后一个 OWNER 降级 → `409 不能撤销门店最后一个店主`。

### 2.5 删除员工

```http
DELETE /shops/{shopId}/staff/{userId}
```

- MANAGER 不能删除 OWNER（403）。
- 删除最后一个 OWNER → `409 不能删除门店最后一个店主`（含店主删除自己）。
- 删除本店 STAFF/MANAGER（有权限时）→ `200`，即时生效（判权不缓存）。

## 三、前端

| 路由 | 页面 | 入口可见性 |
|---|---|---|
| `/staff/verify` | `StaffVerify.vue` 核销台 | 任意员工角色（`/shops/my/staff` 非空） |
| `/staff/manage` | `StaffManage.vue` 员工管理 | 仅 OWNER/MANAGER（按门店过滤） |

`StaffManage.vue`：

- 顶部选择"我管理的门店"（OWNER/MANAGER 身份的门店）；
- 员工表格：userId / 角色 tag / 加入时间 / 行内改角色 / 移出；
- 添加表单：按 userId + 角色；
- 最后一个 OWNER 的降级/移出按钮提前置灰；店长的 OWNER 选项置灰；
- 服务端 409/403/400 的 `msg` 原样展示（例如"该用户已是本店员工"）。

导航（`AppLayout.vue`）同时拉 `myStaffShops`：

- 有任一员工身份 → 显示"核销台"；
- 有 OWNER/MANAGER 身份 → 额外显示"员工管理"。
