# 部署说明（可上线）

> 目标：让项目在**云服务器或本机 VM** 上跑起来，并有一个可访问的地址 —— 这是简历里"可访问链接"那一栏的来源。

---

## 一、两种部署形态（按你现有条件选）

| 形态 | 适用 | 说明 |
|---|---|---|
| **A. 中间件在 VM/本机 Docker，服务用 IDEA 跑** | 日常开发 | 就是你现在的方式，只适合演示录屏 |
| **B. 全部上云服务器（推荐）** | 简历"可访问地址" | 中间件 + 11 个服务都在云端 Docker 里；本地只留 IDEA 写代码 |
| **C. 中间件本地 + 服务打包上云** | 云服务器内存小 | 网络延迟高，不推荐 |

**推荐 B**：学生机 2C4G（约 100 元/年）能跑"最小集"（core profile：gateway + user + shop + item + content），
8G 机器可跑全量 11 个服务。

## 二、构建镜像

> ⚠️ **首次构建需要联网**：本地 Maven 仓库缺插件依赖（plexus-archiver 等），
> 在 IDEA 里 **Reload All Maven Projects** 一次把它们拉下来即可（顺带恢复 actuator 与 ES 依赖）。

```bash
# 在仓库根目录（llmall/）执行
docker build -f deploy/Dockerfile -t local-life/llmall:1.0.0 .
```

镜像内含全部 11 个 jar（单镜像多服务），容器通过 command 指定启动哪个服务。

## 三、准备中间件

### 3.1 VM 现状：接现役容器（**别重建**）

VM（192.168.189.128）上已经在跑中间件，实测清单（2026-10-11）：

| 容器 | 接入前所在网络 | 说明 |
|---|---|---|
| `mysql` | llmall-net | 现役数据库 |
| `nacos` | bridge | 现役注册 / 配置中心 |
| `mq` | llmall-net | **RabbitMQ 的容器名是 `mq`**，不是 `rabbitmq` |
| （无） | — | **Redis 不在容器里**：原生安装，密码 123456 |

```bash
# 1) 建共用网络（只需一次）
docker network create local-life

# 2) 把现役容器接进这个网络
for c in mysql nacos mq; do docker network connect local-life $c; done
#   幂等：重复执行会报 "endpoint with name mysql already exists in network local-life"，
#   那不是失败，恰好说明上一次已经连上了。

# 3) 验收：期望输出 mysql nacos mq
docker network inspect local-life -f '{{range .Containers}}{{.Name}} {{end}}'
docker exec -it mq getent hosts mysql     # 容器间按名字互访（没有 getent 就换 nslookup/ping）
```

> **为什么不用 compose 重建**：新容器会用新数据卷（库表全空），而且现役容器已占用
> 容器名与端口（3306 / 8848 / 5672），`up` 会因为"名字已存在 / 端口已分配"起不来。
> **接网络**是零停机、不动数据的做法。
> 注意 Redis 是原生安装：服务进容器后它只能按宿主 IP 访问（见 `.env.example`）。

### 3.2 全新机器 / 云服务器：用 compose 起一套

```bash
docker network create local-life
docker compose -f ../../docker/docker-compose-infra-lite.yml up -d   # 容器名 mysql/redis/nacos/rabbitmq
# 然后按 sql/merged/README.md 导入库表，并在 Nacos 里导入 nacos-config/ 下的共享配置
```

> ⚠️ 这套的容器名是 `mysql / redis / nacos / rabbitmq`，与 VM 现役的 `mq`、原生 Redis 不同——
> 换环境时改 `.env` 里的 `LLMALL_MQ_HOST` / `LLMALL_REDIS_HOST` 即可，不需要改代码。

> **网络为什么必须统一**：应用容器里用的是容器名（`LLMALL_DB_HOST=mysql`、`NACOS_ADDR=nacos:8848`、
> `LLMALL_ES_HOST=elasticsearch`），只有和中间件处于**同一个 docker 网络**时才解析得到；
> 各 compose 分属不同网络时，典型报错是 `java.net.UnknownHostException: mysql`。
> 三份文件（infra-lite / addon / apps）现在统一接入 external 网络 `local-life`。
>
> ⚠️ `deploy/docker-compose-infra-lite.yml` **已废弃**（内容合并进 `../../docker/docker-compose-infra-lite.yml`），
> 里面只剩说明文字，别再用它起中间件：那份拷贝用的是 `infra-mysql` 这类容器名，和 `.env.example` 对不上。

## 五、Sentinel 控制台（可选，规则以注解为准）

现状：限流/熔断规则由 `@SentinelResource` 注解定义，**控制台不在线也生效**；控制台用于看实时
QPS/RT/拒绝数并动态改规则。地址口径统一为 `${llmall.sentinel.dashboard:localhost:8090}`
（默认值 = 控制台与应用同机；控制台启动命令见 `../README.md` 第九节）。

容器化时由 `.env` 的 `LLMALL_SENTINEL_DASHBOARD` 覆盖，**默认值是按"控制台跑在宿主 Windows"给的**：

```properties
# 控制台在宿主（Windows）：容器经 VMnet8 网关回连宿主，Windows 需放行 8090 入站
LLMALL_SENTINEL_DASHBOARD=192.168.189.1:8090
```

> ⚠️ 规则是**控制台 → 客户端 8719 端口**反向推送的。只配了地址、但控制台回不到客户端时，
> 现象是"机器列表能看到应用、加了流控规则却不生效"。要让推送也通，需要三件事同时满足：
> ① 客户端用 `spring.cloud.sentinel.transport.client-ip` 上报一个控制台可达的地址；
> ② 该地址上的 8719 端口对控制台放行（容器化时把 8719 也 publish 出来）；
> ③ 控制台容器与应用容器在同一 docker 网络（`local-life`）。
> 最省事的做法是**控制台与应用同机**（当前开发形态就是这样）。

## 七、内存与稳定性要点

| 项 | 做法 |
|---|---|
| 每个服务 | `-Xmx192m`，容器 `mem_limit: 256m`（已在 compose 与 Dockerfile 里设好） |
| 中间件 | MySQL 关 `performance_schema`、Redis `maxmemory 96mb`、Nacos `Xmx384m` |
| 云服务器只有 4G | 用 `core` profile，或再维护一份只含必要服务的 compose |
| 启动顺序 | 中间件 → 服务；服务有 Nacos 重试，晚起也能自愈 |
| 优雅停机 | 已在 compose 的 `JAVA_OPTS` 统一加 `-Dserver.shutdown=graceful -Dspring.lifecycle.timeout-per-shutdown-phase=30s`，并设 `stop_grace_period: 40s`（默认 10 秒会把在途下单/核销直接 SIGKILL）。Nacos 共享配置 `shared-log.yaml` 里也放了同一组设置，两条路径任一生效即可 |
| 健康探针 | 所有服务/网关随父 pom 引入 actuator，暴露 `/actuator/health`（含 liveness/readiness 分组）；compose 已配 `healthcheck`（容器内无 curl，用 wget 逐个探测已知端口）。⚠️ **不要把 `/actuator/**` 加进网关白名单**，运维端点只走内网直连 |
| Feign 降级 | `llmall-trade-service` 已补 `spring-cloud-starter-alibaba-sentinel` + `feign.sentinel.enabled: true` —— 否则它声明的 `fallbackFactory` 永远不被调用（Spring Cloud 的 `DefaultTargeter` 不读 fallback，只有 Sentinel 的 Builder 才消费），属"看起来有降级"的假安全 |
| 集中日志配置 | 6 个服务的 `bootstrap.yaml` 都引用 `shared-log.yaml`，该 dataId 必须存在于 Nacos（仓库副本见 `../../nacos-config/shared-log.yaml`）；缺失时 Nacos 会静默忽略，日志格式/级别悄悄回落默认值 |

## 八、时区口径（统一 Asia/Shanghai / CST）

**现行口径（2026-10-12 落地并实测）**：VM 系统、四个中间件容器、Windows 宿主、应用连接串**全部东八区**。

| 位置 | 现状 | 靠什么保证 |
|---|---|---|
| VM 系统 | `Asia/Shanghai`（`timedatectl`，RTC 仍按 UTC 存） | `timedatectl set-timezone Asia/Shanghai`，已持久化 |
| `mysql` 容器 | CST（`@@system_time_zone=CST`，`NOW()` = CST） | 容器 `TZ=Asia/Shanghai`；compose 侧另有 `--default-time-zone=+08:00` |
| `nacos` 容器 | CST | `TZ=Asia/Shanghai` + `/etc/localtime -> Asia/Shanghai` |
| `mq` 容器 | CST | `TZ` + **挂宿主 `/etc/localtime`**（rabbitmq 镜像不带 tzdata，**只设 TZ 是无效的**） |
| `seata-server` 容器 | CST | `TZ` + 挂 `/usr/share/zoneinfo`：1.4.2 是 Alpine 镜像，**连 `jre/lib/zi` 都没有**，只挂 `/etc/localtime` 时 JVM 仍按 UTC 打日志 |
| 应用（IDEA 或容器） | CST | Windows 宿主本就是 CST；`Dockerfile` 有 `ENV TZ=Asia/Shanghai`，apps compose 的 `x-app` 锚点也统一注入 |
| 数据库连接串 | `serverTimezone=Asia/Shanghai` | `nacos-config/shared-jdbc.yaml` |

验证（都是实测过的形态）：

```bash
timedatectl | head -4
for c in mysql nacos mq seata-server; do echo "$c: $(docker exec $c date)"; done
docker logs --tail 1 nacos; docker logs --tail 1 seata-server   # 时间戳应为 CST（11:xx），不是 UTC（03:xx）
docker exec mysql mysql -uroot -p123 -N -e "SELECT @@system_time_zone, NOW();"
```

> ⚠️ **手工改动只活在容器可写层**：`docker cp /etc/localtime`、`ln -sf` 这类修法在 `docker restart`
> 和 VM 重启后都还在，但**容器一旦被 recreate（`docker compose up` 重建、或按 1.5.x 重建 Seata）就全丢**。
> 所以 compose 两份文件都把 `TZ` 与 `/etc/localtime`（Seata 还加 `/usr/share/zoneinfo`）补齐了 ——
> **重建后自带 CST，不用再手工补**。

## 九、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 服务起来但 Nacos 里看不到 | `NACOS_ADDR` 填错，或服务与 Nacos 不在同一 docker 网络（用 `docker exec -it llmall-user-service ping nacos` 验证） |
| 报 `UnknownHostException: mysql` | 同上：容器名解析不到，检查 `docker network inspect local-life` 里有没有 mysql 容器 |
| 报 `Cannot access aliyunmaven ... in offline mode` | 镜像构建时用了 `-o`？去掉离线参数，或先在 IDEA 里联网 reload 一次 |
| 门店详情 500，日志报 Redis 连接失败 | `LLMALL_REDIS_HOST` / `LLMALL_REDIS_PW` 不对（VM 实测 Redis 密码是 **123456**，不是 123） |
| 明明改了配置但不生效 | Nacos 里的共享配置是**远程生效**的，容器内的 `bootstrap.yaml` 只负责拉取；改配置要去 Nacos 控制台改 |
| 云服务器上容器被 OOM Kill | 内存超卖：减少服务数量（core profile）或升配/加 swap |

> 口径提醒：本机 VM 上 RabbitMQ 的**容器名是 mq**（不是 abbitmq），Redis 是原生安装（填宿主 IP）。
> 容器化部署时才用 compose 里的服务名。
